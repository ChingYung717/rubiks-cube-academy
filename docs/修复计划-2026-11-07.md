## 2. 首批：构建权限与可重复部署

### RC-01 · P1 · 部署工作流最小权限

**当前证据**：`.github/workflows/deploy.yml` 在 workflow 级声明 `pages: write`、`id-token: write`，build job 中的依赖安装和测试也继承这些权限。

**实施**：workflow 默认 `contents: read`；build job 仅保留读权限；deploy job 单独授予部署 Pages/OIDC 所需权限，按实际 checkout/部署需求确定 contents 权限。保留 environment、needs 和串行部署配置。OIDC 授权只允许部署 job 请求令牌，不把“能请求令牌”直接等同于所有外部系统都会信任它。

**验收**：build job 无 Pages 写和 OIDC 请求权限；测试/构建失败不部署；普通 PR CI 不获得写权限、不发布；main 成功构建能由 deploy job 发布。核对 GitHub 实际执行日志中的 job 权限，不只静态读 YAML。

### RC-02 · P1 · Action 固定 SHA

检查 `.github/workflows/ci.yml` 与 `deploy.yml`，为 checkout、setup-node、upload-pages-artifact、deploy-pages 的所有调用固定经核验的完整 SHA，保留版本注释；保持现有 `.github/dependabot.yml` 的 github-actions 更新配置。

**验收**：所有实际 uses 均匹配所选发布版本的提交；CI/Pages 功能不回归，Dependabot 能维护固定引用。不为修复而盲目切换未知版本或只复制未核验的 SHA。

### RC-03 · P1 · 默认构建与 Pages 子路径一致

**当前证据**：`vite.config.ts` 无 base，部署命令单独传 `--base=/rubiks-cube-academy/`。这是本地默认产物部署到项目子路径的问题，当前官方 CI 已传参数，不应称线上既有白屏漏洞。

**实施**：统一确定项目默认 base 为 `/rubiks-cube-academy/`，移除 CI 重复参数；如果支持根路径/自定义域名发布，用明确的构建配置覆盖，并在 README 写明命令。检查 public 资源、图标、动态导入等路径，避免只修 index 的 JS 引用。

**验收**：`npm run build` 默认产物在真正的 `/rubiks-cube-academy/` 挂载点加载，所有资源正常；独立验证根路径覆盖模式。不要只依赖 `vite preview` 的宽容行为。使用发布产物核验页面、分包、音效/图标和刷新后的可用性。

## 3. 第二批：记录可靠性、输入和键盘操作

### RC-04 · P1 · 已实现统计回归及存储失败处理

**状态**：累计计数/PB 和 50 条窗口已实现，相关断言在 `src/engine/__tests__/cubeEngine.test.ts`，先验收后决定是否需要修复。

**现存收尾点**：`saveSolveRecords` 分别写入 records 与 stats 两个 key，catch 静默忽略，并返回裁剪后的数组；配额错误可能造成部分写入。需定义一致性恢复和用户提示，不直接宣称现有归档算法整体错误。

**实施与验收**：

1. 复用现有用例，验证 49→50→51→多轮换窗、刷新、历史 PB 被移出窗口、+2/DNF、清空全部、修改最近记录处罚、同 id 不同内容及既有存量迁移。
2. 对第一个/第二个 setItem 分别注入配额错误；定义成功/失败返回，UI 显示“未保存”，重启后计数/PB 不静默回退或重复归档。可评估单个带版本的状态包及迁移，或保留双 key 但实现可核对的恢复协议。
3. 仅有旧版最近 50 条且没有历史汇总时，不可能凭空恢复曾丢失的全部次数/PB；说明迁移口径，不填造统计。
4. 内存和持久化最近记录始终有界。设置和记录损坏仍应安全降级；不得为容错吞掉全部保存错误。

### RC-05 · P2 · 存储输入上限和倍速枚举

`src/utils/storage.ts` 目前仅校验 scramble/createdAt 等字段的类型，倍速接受 `[0.25,4]` 连续范围，而 UI 只提供有限档位。

- 抽取共享倍速枚举（现有 0.5/1/1.5/2），UI 与加载校验共用；非法历史值回退到默认，保留合法历史数据。
- 按应用实际生成格式定义 id、scramble、createdAt 的长度/日期合法性和记录数量边界；明确异常记录的丢弃/提示策略。不要仅因“来自 localStorage”就认定为远程攻击路径。
- 验收正常生成值、超长字符串、非法日期、非有限数字和未知版本；保存失败路径与 RC-04 联动，不产生白屏。

### RC-06 · P2 · 字母快捷键焦点保护

`src/App.tsx` 对 Space 已排除按钮/链接/contenteditable，字母分支仍未统一排除；select 及嵌套可编辑元素也应考虑。抽取统一交互焦点判定，保留魔方舞台的预期快捷键和整体翻转规则。

**验收**：Tab 到按钮、链接、select、嵌套 contenteditable 时 R/L/U/D 等不改变魔方；普通舞台可转动，Shift 逆转、系统修饰键、长按与模态框行为不回归。用键盘浏览器测试验证焦点和状态，不只做静态代码扫描。

### RC-07 · P2 · 记谱指南校准

补齐 E/S、引擎实际支持的宽层转说明，修复 B' 重复“90°”，保留已存在的 x/y/z；区分“引擎可解析”“鼠标可派发”和“键盘有快捷键”，不因文档补全就无意扩展快捷键。对照 `getMoveDefinition` 和 `createStagePointerHandlers` 的实际结果，至少用代表算法与 3D 拖动核对方向。

## 4. 第三批：WebGL 恢复和功耗

### RC-08 · P2 · 有限恢复与主动重试

当前 `Cube3DStage.tsx` 以 ref 累计 context loss，恢复只增加 sceneKey；第三次丢失会进入可操作 2D，未提供重试。此为体验问题，不能称全功能中断。

改为有明确状态的恢复流程：正常、丢失等待、重建中、2D 降级；按恢复稳定窗口或连续失败次数控制预算，而不是恢复回调一触发就无限清零。加入手动“重试 3D”，协调 `App.tsx` 与 Stage 的 webGLUnavailable 状态，避免父组件仍隐藏 3D/2D 控件。无恢复事件时有超时降级。

**验收**：主动 loss/restore、多次快速失败、长时间稳定后再次丢失、恢复超时、初始化失败及手动重试；2D 一直可用，魔方逻辑状态、活动提示箭头和计时状态正确；销毁产生的 loss 不触发无穷重建；重复挂载/卸载无多余监听与 rAF。保留最近提交的单活动指针及 lostpointercapture 防护。

### RC-09 · P3 · 真正按需调度

当前 rAF 每帧续期，跳过 renderer.render 只能减少绘制，不代表没有回调。先测空闲、动画、轨道阻尼时的回调/绘制次数，再考虑 dirty 触发的一次性调度；相机移动、旋转动画、尺寸变化、恢复和提示箭头均须唤醒。不要把显示器刷新率固定写成 60fps。

**验收**：静止后台不持续无意义回调，输入后首帧正常；动画和阻尼能完成，计时仍使用绝对单调时间差；可见性切换后恢复。功能测试与浏览器性能记录分开，不预先承诺电量节省百分比。

## 6. 提交与交付标准

建议独立提交：权限/Action 固定、base 统一、存储失败与统计验收、快捷键/设置校验、WebGL 恢复、记谱说明。统计新功能和多指隔离已经提交，优先回归，不回退为旧实现。GitHub 设置独立记录。

- 改动后运行 `npm test` 与 `npm run build`。当前测试集中在 `src/engine/__tests__/cubeEngine.test.ts`；新增存储/交互测试可按职责拆出，但不为文案微调机械新增测试。
- 浏览器验收：真实子路径产物、键盘焦点、多指拖动、WebGL 主动 loss/restore、计时跨后台与恢复、配额失败提示。记录环境和结果，不能以引擎单测代替浏览器结论。
- Ao5、DNF、+2、绝对时间差计时及新的历史统计是回归基线，不无故重写算法。大版本依赖变更单独回归。
- 完成记录包含提交号、测试命令/退出码、浏览器结果、远端 CI 与 Pages 部署结果。构建通过不等于线上已发布，仓库设置不随代码提交自动生效。

**本轮完成门槛**：build 无部署/OIDC 写权限；Action 固定引用；默认产物可在实际项目子路径运行；历史次数/PB 和配额失败行为经验证；保密报告入口可用。WebGL、快捷键及文档按后续批次独立完成。
